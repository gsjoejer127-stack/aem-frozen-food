# AEM 库存管理 Inventory

一个跑在 **Google Sheet + Apps Script** 上的冷冻食品库存系统。不需要服务器，不收费，手机和电脑都能用。

> 这个文件夹**不会**跟着网站一起部署。它和公开网站完全分开，数据只存在你自己的 Google Sheet 里。

## 功能

| 页面 | 功能 |
|---|---|
| 总览 | 每个产品的可用库存（按箱和包显示），以及低库存、即将到期、已过期三项提醒 |
| 入库 | 选产品（可扫条码）→ 填数量（包或箱）→ 有效期、批号、仓位 → 生成一个新批次 |
| 出库 | 按**先到期先出（FEFO）**自动分配批次并生成拣货单。**过期批次不能出库**，超卖会被拦下 |
| 盘点 | 逐个批次填写实际数量，系统记录差异。报废、损坏、解冻（断冷链）都在这里处理 |
| 到期 | 已过期和 N 天内到期的批次清单，方便安排促销或报废 |
| 记录 | 所有入库、出库、调整记录，包括操作人、单据号和时间。记录只增不改 |

数据都在一个 Google Sheet 里：

- `Products`：产品资料。**安全库存**和**每箱数量**直接在这里改。把"启用"设为 FALSE 可以隐藏产品
- `Batches`：每个入库批次的剩余数量和有效期
- `Movements`：流水账，供审计用
- `Settings`：`expiryWarnDays`（提前几天提醒，默认 30）、`locations`（仓位列表）、`jotformSyncFrom`（见下文）
- `Jotform待处理`：Jotform 生产入库里没法自动入库的记录（见下文）

第一次初始化时，会自动导入网站上的 51 个产品。

## 安装（约 10 分钟，只需做一次）

1. 新建一个 Google Sheet，命名为 `AEM Inventory`。
2. 打开菜单 **扩展程序 → Apps Script**。
3. 在 Apps Script 编辑器里建好以下文件，并把这个文件夹里对应文件的内容贴进去：
   - `Code.gs`（替换默认的 Code.gs 内容）
   - `Logic.gs`：点 **+ → 脚本**，命名为 `Logic`
   - `Seed.gs`：点 **+ → 脚本**，命名为 `Seed`
   - `JotformSync.gs`：点 **+ → 脚本**，命名为 `JotformSync`
   - `Index.html`：点 **+ → HTML**，命名为 `Index`
   - `appsscript.json`：先在 ⚙️ 项目设置里勾选"在编辑器中显示 appsscript.json"，再替换它的内容
4. 在函数下拉框里选 `setup`，点 **运行**，按提示授权。回到 Sheet 就能看到 4 个工作表，产品已经导入。
5. 点 **部署 → 新部署 → 类型：网页应用**：
   - 执行身份：**访问网页应用的用户**
   - 谁可以访问：**拥有 Google 账号的任何人**
   - 部署完成后会得到一个网址。把这个网址加到手机主屏幕，就能当 App 用。
6. **给员工开权限**：把这个 Google Sheet **共享给员工（编辑者）**。
   没有被共享的人即使拿到网址，也读不到任何数据。

> 以后修改代码，要用 **部署 → 管理部署 → 编辑 → 新版本**，网址保持不变。

## 上线前要做的事

1. 在 `Products` 表填好每个产品的**安全库存**（单位是包或件；填 0 表示不提醒）。
2. 做一次**期初盘点**：把仓库现有的货按批次和有效期逐批"入库"。
3. 网站上没有整箱规格的 12 个产品（饺子、腌肉、汤包），如果需要按箱操作，要补填**每箱数量**。

## Jotform 生产入库自动同步

每天 06:00（MYT）把 Jotform **Production Packing Log 生产入库登记**（`261763466729066`）
里的新提交，自动变成库存的**入库批次**。

| Jotform 字段 | 库存里 |
|---|---|
| 产品名称 | SKU：按 `Products` 的 SKU、Name、中文名、**别名**匹配，不区分大小写和空格 |
| 成品入库数量（包） | 入库数量 |
| 入库日期 | **有效期 = 这个日期 + 1 年** |
| 批次号 | 批号 |
| 存储位置 | 位置 |
| 操作员 | 流水的操作人记为 `Jotform/<操作员>` |

**每笔只会入库一次**：入库流水的单据号写成 `JF:<submission ID>`，重复跑也不会重复入库。

**有问题的记录不入库**，会写到 `Jotform待处理` 表并注明原因：

- 产品对不上 → 在 `Products` 的 **Aliases 别名** 栏加上这个写法（多个写法用 `|` 分隔）
- 日期和提交日相差超过 10 天（通常是日/月写反了，会导致有效期错误）
- 包数不是正整数

问题处理好后，下一次同步会自动补入库，状态变成"已入库 B…"。
如果某行不该入库，把状态改成 `忽略`。

### 开启（一次性）

1. Jotform → Settings → API → 建一个 **Read Only** 的 API key。
2. Apps Script → ⚙️ 项目设置 → **脚本属性** → 添加 `JOTFORM_API_KEY` = 这个 key。
   （key 只放在这里，**不要**写进代码或 Sheet。）
3. 在 `Settings` 表填 `jotformSyncFrom`：**期初盘点之后的那一天**。
   之前的生产记录已经算在盘点数里，再导入就会重复。
4. 重新跑一次 `setup`（会补上别名栏和待处理表），然后菜单 **库存 → 立即同步** 试一次，
   看 `Batches` 和 `Jotform待处理`。
5. 没问题后点 **库存 → 开启每日自动同步**。同步失败时 Google 会发邮件给 Sheet 拥有者。

欧洲区 Jotform 账号要另加脚本属性 `JOTFORM_API_BASE` = `https://eu-api.jotform.com`。

用上周（10-05 ~ 10-11）的真实数据测试：25 笔里 19 笔（1,224 包）自动入库；
6 笔进入待处理，分别是鸡翅串（Kepak）、鸡胗串（Pedal）和腌制牛肉。前两种库存里还没有这个产品；
腌制牛肉在生产表里是 2kg 一包，库存里的 `diperap-daging` 是 500g 一包，规格要先统一。

## 已知限制（有意没做的部分）

- **不包含会计、发票和 e-Invoice（MyInvois）。** 这部分建议交给 AutoCount、SQL Account 这类软件。出库时填上发票号或 DO 号，两边就能对账。
- 规模参考：每年几万条流水没有问题。如果到了几十万条，可以把 `Movements` 按年份归档。
- 网页应用以员工本人的身份运行，所以员工必须对 Sheet 有编辑权限，也就**能绕过网页直接改表**。通过网页做的每一步都会记入 `Movements`，直接改表则不会留下流水。可以定期用 Google Sheet 的"版本记录"抽查。如果团队变大、需要更严的权限控制，再升级成带登录和角色权限的独立系统。

## 开发

核心逻辑（FEFO 分配、库存汇总、数量校验）在 `Logic.gs` 里，不依赖 Google 服务，可以在本地测试：

```bash
node --test inventory/test/logic.test.cjs
```
